## 2. 环境

- Windows x64，版本 `10.0.26300.9711`；
- 单一显示器，`2560x1440`，scale factor `1.0`；
- attached interactive desktop，Windows session `2`；
- 非管理员进程；
- 未安装 Visual Studio Spectre-mitigated libraries；
- PoC 使用独立 `CUA_DRIVER_RS_HOME` 与 telemetry 目录，关闭 telemetry、
  cursor overlay 和 macOS permissions gate；
- daemon 使用 `bounded` 权限模式，manifest 只允许 health、应用/窗口枚举、
  窗口观察和 Chrome 窗口资源。写输入、启动应用、浏览器控制和文件写入均未
  授权。

## 3. 二进制与运行时结果

`cua-driver doctor --json` 全部关键探测通过：

- interactive session：通过；
- `CUIAutomation` CoCreate：通过；
- visible window enumeration：通过，首次探测看到 18 个窗口；
- Windows Graphics Capture：通过；
- UIA walk：通过。

受限 daemon 下结果：

| 检查 | 结果 |
| --- | --- |
| `health_report` | `overall=ok` |
| `get_screen_size` | `2560x1440`，scale `1.0` |
| `list_apps` | 339 个已安装/运行条目，其中 18 个 running |
| `list_windows` | 19 个顶层窗口 |

`resources.apps` 授权后，窗口观察成功。这个拒绝说明资源授权确实生效，不是
仅按工具名放行。

## 4. 性能

同一 Chrome 窗口、同一次会话内的观测：

| 模式 | 结果 |
| --- | --- |
| 首次 AX + native screenshot | 约 `7.18s` |
| 再次 AX-only，250 元素预算 | 约 `2.93s` |
| screenshot-only，1280px 长边 | 约 `3.51s` |
| AX + screenshot，1280px 长边 | 约 `3.81s` |

AX-only 返回 `elements_complete=false`，说明在元素预算之外仍有平台 walk
上限或截断。Cortex 不能把“调用成功”解释成“完整看到了窗口”；Observation
必须保留 completeness、truncation reason 和 capture coverage。

这些数字只代表一台高分辨率 Windows 机器和 Chrome，不能外推到 Office、
Electron、UWP、多屏或低配机器。C1 的默认超时必须按平台观测实测设置，
不能沿用 legacy 截图路径的即时假设。

## 5. 源码嵌入调查

pin 到同一 tag 的 `cua-driver-sdk` 可以解析出：

- `CuaDriver::create()` 的同进程 embedded runtime；
- `EmbeddedCuaDriverHost` 启动私有 `cua-driver serve --embedded`；
- typed `list_apps` / `list_windows` / `get_window_state` / action API；
- stable C ABI 与 UniFFI 生成的 wrapper。

当前机器源码编译停在构建前置，而不是 API 不兼容：

```text
No spectre-mitigated libs were found.
```

依赖链通过 `platform-windows -> cua-driver-core` 打开了默认 features，其中
`regorus` 引入 `msvc_spectre_libs`。VS Build Tools 2026 与 MSVC
`14.50.35717` 已安装，但缺少组件：

```text
Microsoft.VisualStudio.Component.VC.Runtimes.x86.x64.Spectre
```

安装该组件需要管理员权限，当前审批环境不能静默完成。发布二进制验证证明
Driver 本身可运行，但不能替代下面两项生产前置：

1. CI/发布机必须安装 Spectre component 并从 pinned source 构建；
2. Windows installer 必须原子携带、签名并校验与主程序匹配的 Driver 文件。

在完成这两项前，不采用本地 checkout 改 feature 的方式伪造“源码构建通过”。

## 6. 当前 go/no-go

### Go

- Cua Driver 在目标 Windows 交互式桌面上能够枚举真实应用、窗口和 Chrome
  UIA；
- 资源级 bounded manifest 确实阻止未授权工具/窗口；
- 发布包签名和 hash 可验证；
- 可以开始实现 `ComputerDriver` 的 Cua adapter，并把 Observation/Receipt/
  Verification 映射到 Cortex policy、approval 和 trace。

### No-go

- 不能把 Cua MCP 直接暴露给模型；
- 不能把 `standard` 或无 manifest 的 daemon 放进生产；
- 不能在没有 macOS embedded-host、签名/notarization 方案时宣称 macOS 可用；
- 不能在云端 Docker/gVisor 里挂本机 Driver，云端仍需要一次性桌面 VM；
- 不能因一次 Chrome 成功而开放通用写操作；
- 不能先开放 `computer_act` 再补 watchdog、secure field 和验证。

## 7. C0 尚未关闭的条件

下列项目仍为 open，C0 报告不能升级成完整 pass：

- 第二个 Windows major/build；
- 100/125/150/200% DPI、双屏、副屏负坐标、旋转屏；
- Notepad、Explorer、Excel 和自绘/UWP fixture；
- 前台与后台输入、focus 抢回；
- secure field、UAC、锁屏、RDP、快速用户切换；
- cancel/panic/timeout 后 modifier 与鼠标按键是否释放；
- 20 个本地任务的完整成功率、时延和输入残留；
- legacy xcap/enigo 与 Cua 的同任务 baseline；
- 源码构建、SBOM、安装包体积与 macOS 签名链。

在这些条件关闭前，C1 只能做 internal dogfood，默认 observe-only；legacy
只保留为迁移基线，不作为生产 fallback。

## 8. 后续 C1 集成结果

条件性 go 之后已经完成最小只读切片：

- `CuaSidecarDriver` 通过专用 named pipe 连接 bounded sidecar；
- 只调用 `start_session/list_windows/get_window_state/end_session`；
- executable allowlist、PID 到 executable 校验、窗口/应用身份映射和截图完整性
  已进入 `ComputerDriver`；
- 模型工具只出现 `computer_list/computer_observe`，没有写工具；
- legacy xcap/enigo 路径不再进入生产工具目录或健康能力；
- 真实 Chrome 路径已完成 list -> observe -> image -> end session 冒烟。
