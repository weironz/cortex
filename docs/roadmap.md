## 现在在哪

M0–M8、N1–N3、R1–R8 与 R10 全部完成，闭环已跑通：

```
CLI / 桌面 / Web  ──►  cortexd  ──►  DeepSeek
                          │
                          ├─ episodes 落库（+ sync_log 同事务）
                          ├─ 异步抽取 facts（双时间轴 + 矛盾消解）
                          ├─ 图片转录 → blob_transcripts（可检索）
                          └─ 四路召回 + RRF → 注入下一轮对话
```

检索基线（116 题真实向量 bge-m3）：
**R@1 0.640 · R@5 0.877 · R@10 0.931 · MRR 0.771**
（逐题型最弱：`跨域检索` R@5 0.667；`应召不到` 误召 0.500）

恢复演练实测（59 MiB 库）：**RPO 46.9 s（稳态上界 = `archive_timeout` 60 s）· RTO 43.6–83 s**；
走加密第二存储取回再恢复：**RPO 50.9 s · RTO 67.7 s**（异地取回 30 s 不计入）。

工具执行有 OS 沙箱（Linux landlock+seccomp / macOS Seatbelt），
逃逸测试在容器里实跑；**没有沙箱能力的平台默认拒绝执行**。

### R9 · 认证与多租户

现在是单用户自托管，`cortexd` 谁连上谁就是主人。
给别人用之前这条必须有。

### R11 · 工具确认回路 —— 现在 `shell` 是被硬拒着的

沙箱那轮顺带加了 `shell` 工具，但 `ApprovalPolicy` 只有「拦」与「放」两态，
没有「问」：真正的拦截要一条服务端问、客户端答的回路
（`ChatEvent::ConfirmRequest` + 回执端点 + 在 `Turn::run` 里挂起等待）。

在那之前 `Risk::Execute` **恒拒** —— 于是 `shell` 写好了却用不了。
这不是遗漏，是刻意选的安全侧：口子在还没打开时关掉是零成本的。
但它也意味着**编码场景目前只能读写文件，不能跑命令**，
接上这条回路才算真的可用。

闸门的位置已经钉死在 `ApprovalPolicy::decide`，调用点一行都不用动。

## 已知但不排期

| 事项 | 为什么不排 |
|---|---|
| **ASR** | 三条路都堵：本地 Whisper 要绑 C 依赖 + 六端交叉编译；云 API 得自己写 HTTP 客户端（正是取件要避开的活）；最近的一条是多模态 LLM 直接吃音频，**缺口只在 goose 的 `MessageContent` 没有 Audio 变体**。补齐约等于「一个变体 + 一个 `convert_audio`」，等上游或等一个明确需求 |
| **应召不到误召 0.500** | 干扰项在语义上确实最近（「B302 会议室」vs「B301」）。判定为**检索单独解决不了**，需要生成侧参与 |
| 会话标题改回派生 | 没有 unrename 操作，要放宽 CHECK 约束 + 迁移。收益太小 |
| `retrieval_traces` 遥测表 | 四路各自排名 / 融合排名 / 实际注入 / 模型是否引用。**逐路记录**才能归因。豁免同步与「永不删除」 |
| `relates_to` 跨域连接 | 夜间扫描跨 domain 候选对，追加低 confidence 的 `relates_to`——图遍历自动带出另一侧，**无需改检索代码**。融合时该通道需豁免域惩罚 |
| 摘要粒度 | 主题级与时段级的划分方式未定 |
| 视频处理 | 抽帧频率、场景切分。投入产出比在 v1 不成立 |
| 移动端 | 桌面与 Web 先跑通；移动端是采集端，可后置 |
| cross-encoder | 先用 RRF。等评测集证明不足再上 |
| `entity_merges` 撤销 | 现为 first-writer-wins + 不可逆 |
| HA | 单机自托管，恢复期间服务是停的，RTO 就是停机时间 |
| **离线** | 客户端是瘦客户端，断网就用不了。早期设计里的「本地 SQLite 缓存 + 离线写队列」没有实现，因为 agent 循环留在了服务端（理由见 README）。要补的话是一整套：本地缓存 + 写队列 + 冲突处理——append-only 让冲突处理简单，但工具执行在离线时无处可跑，那才是真障碍 |

## 并行策略

非冲突任务交子 agent 并行。冲突面按**目录**划，不按功能划——
功能会互相牵扯，目录不会。

上一轮四个 agent 的边界：`crates/cortex-llm+memory`（多模态）·
`crates/cortexd+store`（会话生命周期）· `app/`（Flutter）·
`scripts/+.github/`（运维），零冲突。

R1–R5 的自然切法：R1+R2+R3+R4 都动 `cortexd` 的 DTO 与 `store`，
**必须串行或同一个 agent 做**；R5 独立（新回扫器）；R6–R8 全在 `scripts/`。

## 演示场景（做完什么算「能给别人看」）

但 caption 质量受 vision 模型限制——8B 模型有 OCR 抖动，生产要指到更大的模型。
