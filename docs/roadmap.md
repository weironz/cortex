## 现在在哪

M0–M8、N1–N3、R1–R8 与 R10 全部完成，闭环已跑通：

```
CLI / 桌面 / Web  ──►  cortexd  ──►  DeepSeek
                          │
                          ├─ episodes 落库（+ sync_log 同事务）
                          ├─ 异步抽取 facts（双时间轴 + 矛盾消解）
                          ├─ 图片转录 → blob_transcripts（可检索）
                          └─ 四路召回 + RRF → 注入下一轮对话
```

检索基线（116 题真实向量 bge-m3）：
**R@1 0.640 · R@5 0.877 · R@10 0.931 · MRR 0.771**
（逐题型最弱：`跨域检索` R@5 0.667；`应召不到` 误召 0.500）

恢复演练实测（59 MiB 库）：**RPO 46.9 s（稳态上界 = `archive_timeout` 60 s）· RTO 43.6–83 s**；
走加密第二存储取回再恢复：**RPO 50.9 s · RTO 67.7 s**（异地取回 30 s 不计入）。

工具执行有 OS 沙箱（Linux landlock+seccomp / macOS Seatbelt），
逃逸测试在容器里实跑；**没有沙箱能力的平台默认拒绝执行**。

## 下一批 —— 挡在「敢给别人用」前面的

> 「日常自己用」的五条（R1~R5）与运维三条（R6~R8）、沙箱（R10）
> 均已完成，见 [roadmap-done.md](roadmap-done.md)。

### R9 · 认证与多租户

现在是单用户自托管，`cortexd` 谁连上谁就是主人。
给别人用之前这条必须有。

### R11 · 工具确认回路 —— 现在 `shell` 是被硬拒着的

沙箱那轮顺带加了 `shell` 工具，但 `ApprovalPolicy` 只有「拦」与「放」两态，
没有「问」：真正的拦截要一条服务端问、客户端答的回路
（`ChatEvent::ConfirmRequest` + 回执端点 + 在 `Turn::run` 里挂起等待）。

在那之前 `Risk::Execute` **恒拒** —— 于是 `shell` 写好了却用不了。
这不是遗漏，是刻意选的安全侧：口子在还没打开时关掉是零成本的。
但它也意味着**编码场景目前只能读写文件，不能跑命令**，
接上这条回路才算真的可用。

闸门的位置已经钉死在 `ApprovalPolicy::decide`，调用点一行都不用动。

### D · 本地 agent —— 编码那一半现在**不工作**

裁决与全部否决理由见 [architecture.md 一、总体架构](architecture.md)，
这里只列要做的事。

**问题**：工具跑在 cortexd 进程内（`cortex_agent::tools::execute` 直接
`std::fs::*`），也就是说 agent 读写的是**服务器**上的目录 —— 用户本地的代码
它看不见。桌面安装程序装完只剩一个填服务器地址的空壳，只是这件事露在外面的一角。

**做法**：把 agent 循环搬到本地。本地那个进程 ≈ **现在的 cortexd 去掉数据库**，
所以不是造新东西。四步，前三步做完「装完能用」就成立：

| | 做什么 | 之后能干什么 |
|---|---|---|
| D1 | cortexd 加 `GET /memory/context`（检索 + 渲染成注入块）、`POST /episodes`（写回 + 触发抽取）、`POST /llm/stream`（**可选**的 LLM 代理） | 本地进程能拿到记忆 |
| D2 | 本地 agent 二进制：复用 `cortex-agent` 的循环、工具与沙箱，记忆访问换成上面三个端点 | 命令行里先跑通 |
| D3 | 安装程序把它与 GUI 一起装、随 GUI 起、绑 `127.0.0.1`。**先解 D0** | **装完能用** |
| D4 | 会话绑定从「服务器上的目录」改成「本地某个目录」 | 编码那一半真的成立 |

**D0 · Windows 沙箱 —— D3 的前置阻塞项**

两个各自都对的决定撞在一起了：

- 桌面安装程序**只发 Windows**（0.1.1 的决定）
- Windows **没有** landlock / seatbelt 的对应物 → `Capability::Unavailable`
  → **默认拒绝执行工具**

于是 D 落地后，Windows 用户装完会发现 **agent 一个文件都不肯写**，
除非手动 `CORTEX_SANDBOX=unsandboxed` —— 那等于把安全兜底整个关掉。
**这不是「以后再说」，它挡着 D3。**

候选方向（都没做，各自要评估）：Windows AppContainer / Job Object、
把工具跑进受限子进程、或者对 `Risk::Read`/`Write` 分级放行而
只对 `Risk::Execute` 保持硬拒。

> 这条是外部评审提出来的，虽然他担心的是「裸奔」而实际问题正好相反
> （装了用不了）—— 但没有那一问不会去撞这两条决定。

**其余要注意的**：

- **注入块格式会变成跨进程契约**。`GET /memory/context` 返回渲染好的块，
  本地 agent 与 cortexd 独立发版 —— 格式漂移**不会报错**，只是模型收到
  一段结构不对的记忆，效果悄悄变差。要么给它版本号，要么把渲染留在本地
  而端点只回结构化数据
- **协议版本兼容**：「本地能跑但记忆接口不兼容」是一类全新故障。
  不兼容时应当**拒绝启动并说清楚**，不是降级运行
- **进程健壮性与自动更新**：本地进程挂了 = agent 整个不可用。
  崩溃恢复 / 自动拉起 / 日志 / 自动更新（不做更新，版本碎片化会把上一条放大）
- **会话执行状态 ≠ 记忆**：跑到一半切到另一端，恢复得了历史、恢复不了
  执行上下文。`confirm.rs` 对「待确认项」已有裁决（刻意不落库），
  但更广的「会话状态要不要同步」**还没想过** —— 想清楚之前别顺手落库
- **LLM 两条路都要留**：默认经 cortexd 代理（key 只在服务端一处），
  也可本地直连（key 在本地 `.env`）。只留代理会让「想换个模型」变成
  「得去改服务器」，而自托管场景下用它的人就是运维
- **连不上 cortexd 时是「变成 Claude Code」，不是「打不开」** ——
  循环、工具、shell、LLM 照常，界面上明说「记忆未连接」。
  写入不丢（本地 append-only 队列，联网后灌回去），**但不存第二份记忆库**
- 这会**改 HTTP 契约**，所以要在 0.x 里做，不能等

### E · remote control —— Web 挂到在线的本地 agent

> **CLI 不走这条。** 它和你的文件在同一台机器上，D2 之后直接连
> `127.0.0.1` 的本地 agent 即可（没起就拉起来，codex app-server 形态）。
> 需要中继的只有 Web 与「另一台设备上的 GUI」。

本地 agent 跑完整会话，cortexd 只当**中继**，Web/CLI 挂上去看和操作
（形态像 VS Code Remote）。跨网络的是 **UI 事件流**，不是每一次工具调用 ——
这是它与被否决的「工具外派」的全部差别，代价差一个量级。

做完之后 Web 的限制就只在**一台在线桌面都没有**时成立。

> 顺带纠正一个容易传开的误解：**CLI 与 Web 现在都不是「只能聊天」**。
> CLI 会渲染工具事件、能答确认；Web 有附件上传下载、图片理解、
> markdown + 代码高亮。**唯一由架构决定的限制是「不能操作你机器上的文件」**。
> 与 ChatGPT / Claude 的真实差距在**生成侧**（生成图片、生成 Word/PPT/Excel —— 都没有），
> 那是独立的产品缺口，不在 D/E 的范围里。逐项对照见
> [architecture.md](architecture.md)「CLI 与 Web 现在到底能做什么」。

依赖 D2（得先有本地 agent 可挂）。

### F · 生成侧 —— 生成图片 / 生成文档

与 D/E **无关**的独立缺口。接收侧我们不差（附件上传下载、图片理解、
markdown + 代码高亮都有，逐项见 [architecture.md](architecture.md)），
差的全在生成侧：

| | 现状 | 要做什么 |
|---|---|---|
| 生成图片 | ❌ 一个供应商都没接 | 一个工具 + 一家供应商（DashScope / 即梦 / OpenAI images）。产出走已有的 blob 通道，与上传的图同一条路 |
| 生成 Word / Excel | ❌ | 一个工具 + 一个库（`docx-rs` / `rust_xlsxwriter`） |
| 生成 PPT | ❌ | 同上，但 Rust 侧没有成熟库，可能要让 agent 写脚本调 `python-pptx` —— 那要求沙箱里有 python，先想清楚 |
| diff 视图 / 终端 ANSI | ❌ | 「富文本四件套」剩下的两件，见「三、已接受的代价」 |

> **D 会让「生成文档」变成一件更好的事。** 生成文档本质是**写文件**，
> 而 D 之后写文件是**本地**工具 —— 生成的 .docx 直接出现在你的目录里，
> 而不是像 ChatGPT 那样给你一个下载链接再手动放好。
> 所以 F 排在 D 之后做，收益更大且实现更简单（不用管上传回传）。

### G · 派 agent 去云上干活 —— **不用建，别删就行**

「让 agent 自己在别处跑一段时间，回来交活」这个能力**今天就有**：
cortexd 里已经有 `Live::workspace_turn`、会话绑定工作区（`bind_workspace`
session 事件）、以及 compose 里的 `cortex-prod-workspace` 卷。
也就是说服务端那条循环**本来就是一个云上工作区 agent**。

我们一直把它当缺陷看（「工具动的是服务器的文件」），但那只在
「我要它改我本机的代码」这个场景下是缺陷。换个场景它正好：
克隆一个仓库到云上工作区、让它跑两小时、回来看结果 —— 关掉笔记本也照跑。

**所以 D 的正确做法是「加一条本地路径」，不是「删掉服务端那条」**：

| 场景 | 走哪条 |
|---|---|
| 改我本机的代码 / 文档 | 本地 agent（D） |
| 派出去干活，关掉笔记本也照跑 | 服务端循环（**已有**） |
| 没有在线桌面时随便聊两句 | 服务端循环（已有） |

要补的只有产品化的部分：给它一个明确的入口（「派出去」而不是碰巧
绑了工作区）、任务状态可见、跑完通知。**不是新架构。**

> **这里有个我们独有的东西**：派出去的 agent 与你共用**同一个记忆权威**。
> 它在云上学到的东西直接进你的记忆，回来不用「汇报」——
> Devin 那类云 agent 的产出是一个 PR，学到的过程随容器一起消失。
> 这一条值得在演示里专门做一遍。

## 已知但不排期

| 事项 | 为什么不排 |
|---|---|
| **ASR** | 三条路都堵：本地 Whisper 要绑 C 依赖 + 六端交叉编译；云 API 得自己写 HTTP 客户端（正是取件要避开的活）；最近的一条是多模态 LLM 直接吃音频，**缺口只在 goose 的 `MessageContent` 没有 Audio 变体**。补齐约等于「一个变体 + 一个 `convert_audio`」，等上游或等一个明确需求 |
| **应召不到误召 0.500** | 干扰项在语义上确实最近（「B302 会议室」vs「B301」）。判定为**检索单独解决不了**，需要生成侧参与 |
| 会话标题改回派生 | 没有 unrename 操作，要放宽 CHECK 约束 + 迁移。收益太小 |
| `retrieval_traces` 遥测表 | 四路各自排名 / 融合排名 / 实际注入 / 模型是否引用。**逐路记录**才能归因。豁免同步与「永不删除」 |
| `relates_to` 跨域连接 | 夜间扫描跨 domain 候选对，追加低 confidence 的 `relates_to`——图遍历自动带出另一侧，**无需改检索代码**。融合时该通道需豁免域惩罚 |
| 摘要粒度 | 主题级与时段级的划分方式未定 |
| 视频处理 | 抽帧频率、场景切分。投入产出比在 v1 不成立 |
| 移动端 | 桌面与 Web 先跑通；移动端是采集端，可后置 |
| cross-encoder | 先用 RRF。等评测集证明不足再上 |
| `entity_merges` 撤销 | 现为 first-writer-wins + 不可逆 |
| HA | 单机自托管，恢复期间服务是停的，RTO 就是停机时间 |
| **离线检索** | 定案：**不做本地第二个检索引擎**。它不是「加一个本地库」，是把整个检索引擎写第二遍（pgvector / tsvector / advisory lock 在 SQLite 上都没有对应物），而且第二遍必然更弱、失效方式静默。离线时还算不出 embedding、调不了抽取用的 LLM。**能做的是写入不丢**（本地 append-only 队列，见 D）。真要离线完整可用，答案是把 cortexd 跑在 localhost —— 但那会变成两个 cortexd 要互相同步，而 `sync_log` 只有服务端→客户端的单向拉取，**没有服务端间的多主同步**。完整理由见 [architecture.md](architecture.md) |
| **服务端之间的多主同步** | 上一行的前置。冲突、因果序、双向游标都要重新设计，[memory.md §九](memory.md) 把星型拓扑写死正是为了不碰它 |

## 获客钩子（v1 前值得做）

**① 外部记忆一键导入**：ChatGPT / Claude 导出文件导入，合成 `kind=import` 的
episode 作出处锚点（**无需改 schema**）。
「记忆搬家」正在成为战场，供应商中立 + 自托管是天然的「搬家终点」。

形态吻合得出奇：他们导出的是**对话**，而抽取管线的输入正好就是对话 ——
导入器是「格式适配器 + 跑一遍已有的抽取」，大半是复用。
「把你三年的 ChatGPT 历史导进来，它就有记忆了」这句话是能兑现的。

两个必须写在前面的代价：**要花钱**（三年历史 = 大量抽取调用，得有预算闸门
与进度条，不能默默烧）；**必须硬套 [memory-content.md](memory-content.md)
的过滤规则** —— 批量导入是「什么都进记忆」这个失败模式最容易发生的地方，
尤其是情绪推断禁令与第三方私人属性，历史对话里遍地都是。

**② 导出自己的记忆**：**现在完全没有**（只有 `pg_basebackup` 那套运维备份，
那是给运维恢复用的，不是给用户带走数据用的）。一个以「永不丢失」为承诺的
产品拿不走自己的数据是自相矛盾的，而且 [memory-content.md](memory-content.md)
已经写了 GDPR 的数据可携带权。工作量小，**该早做**。

**③ MCP 接入：让别的 agent 用我们的记忆**。一个 MCP server 暴露
`memory_search` / `memory_add`，端点基本都有了，是包装工作。

但要写清一处落差：**作为插件交出去的是内容，控制不了位置**。
注入契约（稳定块进可缓存前缀，见 [CLAUDE.md](../CLAUDE.md) 不可违反的约束 #4）
在 MCP 形态下拿不到 —— 宿主 agent 决定把工具返回值放哪。
接进 Claude Code 的用户得到「能检索到你的记忆」，得不到「前缀缓存不被打穿」。

③ 同时是一条**战略岔路**：做完它，「Cortex 是记忆层」这条路就基本免费拿到了，
而它与「Cortex 是完整的 agent」是两个不同的对手（mem0 / Zep vs Claude Code）。
不必现在拍板 —— D1 那三个端点在两条路上都要建。

## 并行策略

非冲突任务交子 agent 并行。冲突面按**目录**划，不按功能划——
功能会互相牵扯，目录不会。

上一轮四个 agent 的边界：`crates/cortex-llm+memory`（多模态）·
`crates/cortexd+store`（会话生命周期）· `app/`（Flutter）·
`scripts/+.github/`（运维），零冲突。

R1–R5 的自然切法：R1+R2+R3+R4 都动 `cortexd` 的 DTO 与 `store`，
**必须串行或同一个 agent 做**；R5 独立（新回扫器）；R6–R8 全在 `scripts/`。

## 演示场景（做完什么算「能给别人看」）

1. CLI 里聊技术选型 → 换桌面端问「我们上次定的对象存储是什么」→ 答对且能点开出处
2. 改主意换方案 → 问「现在用什么」答新的，问「三个月前我以为用什么」答旧的
3. 发一张架构截图 → 过几天问「那张图里的组件有哪些」→ 能召回

前两条**已经能跑**。第三条链路已通（图片转录入库），
但 caption 质量受 vision 模型限制——8B 模型有 OCR 抖动，生产要指到更大的模型。
