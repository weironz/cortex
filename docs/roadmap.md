## 下一批 —— 挡在「日常自己用」前面的

### R1 · 长会话会丢最新的话 ⚠️ 数据可见性缺陷

`GET /sessions/{id}` 是 `ORDER BY occurred_at ASC LIMIT 500`。
超过 500 轮的会话，**丢掉的是最新的那些**——用户看到的是一段没有结尾的对话。
客户端现在靠比对 `message_count` 打横幅提示，那是止血不是修复。

改成游标分页且**默认最新在前**。这条排在最前不是因为难，
是因为它是唯一一个「用户会相信一个错误画面」的缺陷。

### R2 · 回放的历史轮次没有记忆抽屉

`episodes` 不逐行存注入的记忆与工具调用，于是**同一个回答刷新前后长得不一样**：
刚生成时能点开「为什么记得这个」，重开会话后那个抽屉是空的。

出处可查是这个项目的核心卖点，只在内存里活着等于没有。
落库口径要一并定：存 fact id 列表（省空间、但 fact 可能已失效）
还是存注入时的快照（可回放、但冗余）。倾向前者 + 失效标记。

### R3 · 附件回放只剩一串哈希

`AttachmentRef` 只有 hash，没有 `filename` / `mime` / `size_bytes`。
重开会话时一个 PDF 只能显示「文档 · a1b2c3d4」。

### R4 · 工具事件让客户端猜路径

`ChatEvent::Tool` 不带 `path`，Flutter 现在从渲染后的参数字符串里正则抠文件名。
参数格式一变客户端就静默显示错文件。加 `path: Option<String>`。

### R5 · 预签名直传的图片进不了记忆

大于 32 MiB 走 presign 直传，服务端从不经手字节，转录管线无从触发——
**大文件是纯归档，检索不到**。需要一个后台回扫器：
以 `blobs` 表为清单，找出没有 `blob_transcripts` 的可转录类型补跑。

## 下一批 —— 挡在「敢给别人用」前面的

### R6 · 备份不加密

落到第二存储是明文。异地存储不可信时这是敞口。

### R7 · 备份没有告警

`backup-all.sh` 返回非零码，但没人看退出码。
**光有退出码不算有告警**——失败与从没跑过在现象上完全一样。

### R8 · purge 抹不干净

只清主存储与镜像，历史 WAL 与旧全量里仍残留。
彻底抹除必须同时轮转备份——这条已写进 operations.md，但没有工具支持。

### R9 · 认证与多租户

现在是单用户自托管，`cortexd` 谁连上谁就是主人。
给别人用之前这条必须有。

### R10 · 沙箱

工具执行现在只有路径围栏 + 权限确认，没有真沙箱。
从 codex 取件（`execpolicy` / `linux-sandbox`）。

## 已知但不排期

| 事项 | 为什么不排 |
|---|---|
| **ASR** | 三条路都堵：本地 Whisper 要绑 C 依赖 + 六端交叉编译；云 API 得自己写 HTTP 客户端（正是取件要避开的活）；最近的一条是多模态 LLM 直接吃音频，**缺口只在 goose 的 `MessageContent` 没有 Audio 变体**。补齐约等于「一个变体 + 一个 `convert_audio`」，等上游或等一个明确需求 |
| **应召不到误召 0.500** | 干扰项在语义上确实最近（「B302 会议室」vs「B301」）。判定为**检索单独解决不了**，需要生成侧参与 |
| 会话标题改回派生 | 没有 unrename 操作，要放宽 CHECK 约束 + 迁移。收益太小 |
| `retrieval_traces` 遥测表 | 四路各自排名 / 融合排名 / 实际注入 / 模型是否引用。**逐路记录**才能归因。豁免同步与「永不删除」 |
| `relates_to` 跨域连接 | 夜间扫描跨 domain 候选对，追加低 confidence 的 `relates_to`——图遍历自动带出另一侧，**无需改检索代码**。融合时该通道需豁免域惩罚 |
| 摘要粒度 | 主题级与时段级的划分方式未定 |
| 视频处理 | 抽帧频率、场景切分。投入产出比在 v1 不成立 |
| 移动端 | 桌面与 Web 先跑通；移动端是采集端，可后置 |
| cross-encoder | 先用 RRF。等评测集证明不足再上 |
| `entity_merges` 撤销 | 现为 first-writer-wins + 不可逆 |
| HA | 单机自托管，恢复期间服务是停的，RTO 就是停机时间 |

## 并行策略

非冲突任务交子 agent 并行。冲突面按**目录**划，不按功能划——
功能会互相牵扯，目录不会。

上一轮四个 agent 的边界：`crates/cortex-llm+memory`（多模态）·
`crates/cortexd+store`（会话生命周期）· `app/`（Flutter）·
`scripts/+.github/`（运维），零冲突。

R1–R5 的自然切法：R1+R2+R3+R4 都动 `cortexd` 的 DTO 与 `store`，
**必须串行或同一个 agent 做**；R5 独立（新回扫器）；R6–R8 全在 `scripts/`。

## 演示场景（做完什么算「能给别人看」）

1. CLI 里聊技术选型 → 换桌面端问「我们上次定的对象存储是什么」→ 答对且能点开出处
2. 改主意换方案 → 问「现在用什么」答新的，问「三个月前我以为用什么」答旧的
3. 发一张架构截图 → 过几天问「那张图里的组件有哪些」→ 能召回

前两条**已经能跑**。第三条链路已通（图片转录入库），
但 caption 质量受 vision 模型限制——8B 模型有 OCR 抖动，生产要指到更大的模型。
