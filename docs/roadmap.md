### 2026-08-23 新增：智能体 / 技能 / 连接器 / 电脑操作

四样一起做的，因为它们回答的是同一个问题的四个面：**模型手上有什么、
它以什么身份说话**。

| | 是什么 | 在哪儿 | 关键约束 |
|---|---|---|---|
| **智能体** | 一份存下来的人设 | 左栏第三个入口，卡片墙 | 换人设 = 开新对话（中途换会打穿 prompt caching，且历史前后不一致） |
| **技能** | 一份写好的做法 | 设置 → 技能 | 目录每轮进提示词，正文由 `load_skill` 按需取回 |
| **连接器** | MCP 的说人话入口 | 设置 → 连接器 | 不新造机制；四条一键精选 + 原来那套全保留 |
| **电脑操作** | 截屏 + 键鼠 | 设置 → 连接器最下面 | 默认关；这是产品里权限最大的一组 |

**四样共用一条纪律**（CLAUDE.md 约束 2 的四次具体应用）：能力与它在提示词 /
工具目录里的广告**同生共死，判据只算一处**。

* 技能：`Caps.has_skills` 同时决定「印不印目录」与「摆不摆 `load_skill`」；
* 电脑操作：`Caps.can_use_computer` 同时决定「印不印坐标系说明」与「摆不摆
  那五个工具」；
* 智能体：空人设在**控制器**里就滤掉，不留给某一条传输去挡；
* 连接器：精选里每个包名都对 npm registry 查过，已接过的不给再点（`PUT` 是
  覆盖，会盖掉用户改过的 trust 与填过的 key）。

各自的完整理由在 [design.md](design.md) 第十二～十五节与
[architecture.md](architecture.md)。三处踩过的真坑：

* `/agents` 已经是本机 agent 的心跳注册，智能体只能叫 `assistants`
  （撞上时 axum 直接 panic）；
* `GET /skills/body` 得进委托令牌白名单 —— 漏了的话云端会话里 `load_skill`
  连吃 403，而桌面端一切正常；
* 电脑操作拿一个不支持 vision 的模型开着，代价是**屏幕白拍一次并已经发给
  供应商**（截图在工具执行时才拍）。

## 手头挂着的

### 模型能力判定：目录说不出来的那一大片

**病灶**：一个模型能不能看图 / 调工具 / 生图，我们有两个源，而且都会漏。

| 源 | 谁读它 | 漏在哪 |
|---|---|---|
| 供应商定义（`crates/cortex-llm/src/definitions/*.json`） | 服务端 `ensure_can_see` | 只覆盖内置那几家，手写 |
| models.dev 目录（编译期嵌进二进制的 2.97 MB 快照） | 界面徽标与筛选（`describe_all`） | **新模型永远慢一拍**；用户自带的中转站永远不在里面 |

2026-08-26 的实例：DeepSeek 8-21 上线 `deepseek-v4-flash-vision-exp`，
两个源**都不认识它**。表现是「获取模型列表」里根本没有它（部署那条来源
只列定义里硬编码的四个名字），而就算实拉到了，能力也全是 null，
一用「视觉」筛选就消失。

**这一整块 2026-08-26 做完了。** 四级回落已经落地，全仓库只此一处解析
（`cortex_llm::caps::resolve`）：

| 优先级 | 来源 | 落点 |
|---|---|---|
| 1 | **用户手工覆盖** | `model_sources.caps_overrides`，设置页「编辑模型」面板 |
| 2 | **接口实时探测** | `model_sources.probed_caps`，`cortex_llm::probe`（OpenRouter / Ollama）|
| 3 | models.dev 目录 | 编译期快照 |
| 4 | 供应商定义 | 我们自己写的 JSON（**服务端闸门读的也是它**）|

读它的有**四处**，四处都必须读到同一份：

| 谁 | 读它干什么 |
|---|---|
| 设置页（`describe_all_with`） | 画能力徽标、给「编辑模型」面板预选 |
| 聊天的模型选择器（`/llm/models`） | 同上，外加「视觉」那个筛选 |
| 发送闸门（`ensure_can_see`） | 贴了图而模型看不懂时拦在发送之前 |
| **自动档**（`model_pick::cheapest`） | 排除干不了这活的候选 |

⚠️ **少喂给其中任何一处都不会报错**，而症状是「同一个模型在两个界面上
说两句话」。同一个错法在 2026-08-26 一天里犯了三次：覆盖没接到选择器上、
探测没接到选择器上、覆盖与探测都没接到自动档上 —— 每一次另外那几处
看起来都完全正常。

所以现在这几样绑成了一个类型（`model_sources::SourceCaps`），且只有
`of(&ModelSource)` 与 `none()` 两个构造函数：**列出一条来源的身份、
却给它另一条来源的能力上下文，是编译不过的**。

⚠️ 自动档里「不知道」= 不选，与发送闸门的三态**故意相反**：闸门放行是
因为那个模型是用户自己选的，我们没有立场替他拦；自动档挑的是我们，
在有把握的候选里挑一个心里没底的，出了事是我们替他选错了。

调研过的十个同类产品（结论见 [roadmap-done.md](roadmap-done.md) 那一节）
一致做法就是这三件套 —— 接口能问的先问、问不出来落目录、目录也没有才手动补：

| 供应商 | 接口说不说得出能力 |
|---|---|
| OpenRouter | ✅ 最富。`architecture.input_modalities` 给 `["text","image","file"]`，还能服务端筛 `?input_modalities=image`。一家覆盖 400+ 模型 |
| Ollama | ✅ 但要两步：`/api/tags` 列名 → 逐个 `/api/show` 拿 `capabilities: ["completion","vision","tools","thinking"]` |
| OpenAI / Anthropic / DeepSeek / 多数 OpenAI 兼容中转站 | ❌ 只有 `id`/`created`/`owned_by` |

✅ **接缝已经绕开了**（不是拓宽）：goose 的 `fetch_supported_models` 签名是
`Vec<String>`，只回名字。改它要动取件自 goose 的 `cortex-providers`，那意味着
以后每次同步上游都要重打补丁 —— 所以另开了一条只做能力探测的窄路
（`cortex_llm::probe`），它不参与调模型，失败了回落到目录即可。

✅ **手动覆盖覆盖了四位**（vision / tool_call / reasoning / image_output）
外加显示名与上下文；优先级定死为 手动 > 接口 > 目录 > 定义。

⚠️ **保存时只写用户真按过的那几位。** 界面上预先选中的多半来自自动结论，
而选中不等于按过 —— 一并写进去等于把此刻的结论固化成他的断言，而**冻错了
察觉不到**（症状与「这个模型真的不支持」一模一样）。

⚠️ 抄一个现成的坑：[openclaw#44647](https://github.com/openclaw/openclaw/issues/44647)
—— 只调 `/api/tags` 不调 `/api/show`，于是所有 Ollama 模型被打成 text-only，
用户手改配置每次重启被覆盖。与上面那个实例是同一个形状。

**顺带能被同一件事解决的一个悬案**（2026-08-26 核实到这一步）：
官方定价页只列 `deepseek-v4-pro` / `deepseek-v4-flash` /
`deepseek-v4-flash-vision-exp` 三个（都是 **1M 上下文**，已按此写进定义），
而 `deepseek-chat` / `deepseek-reasoner` **整页不出现**。没进定价页不等于
已下线，所以两者留在定义里、`context_limit` 保守留 128000 未动 ——
猜大了的代价是字已经吐给用户之后被供应商拒掉那一轮。

**实拉一次就知道答案**：那两个别名今天还认不认、上下文多少，`/v1/models`
说了算。所以别把这条当成独立的考据任务，它会随上面那件事一起了结。

**为什么假阴性比假阳性贵**：所有同类产品 issue 区的主要噪音都是假阴性 ——
能看图的模型被判成不能，入口消失且不解释。而我们放行的判据是
「没确认没有」（`vision != false`），筛选的判据才是「确认有」
（`vision == true`）——**这两处不是同一条，别去「统一」它们。**

### E · 任何在线的 agent 都能被挂上去（原「Web 挂到在线的本地 agent」）

> **CLI 不走这条。** 它和你的文件在同一台机器上，直接连 `127.0.0.1` 的本地
> agent 即可（没起就拉起来）。需要中继的只有 Web 与「另一台设备上的 GUI」。

本地 agent 跑完整会话，agentd 只当**中继**，Web/CLI 挂上去看和操作。跨网络的
是 **UI 事件流**，不是每一次工具调用 —— 这是它与被否决的「工具外派」的全部
差别，代价差一个量级。做完之后 Web 的限制就只在**一台在线桌面都没有**时成立。

**2026-08-17 重新框过一次，并做了一路调研**（[references.md](references.md)
「远程挂载与多端」）。原来写的是一个特例（Web 挂到本地 agent），现在的框法是
**「哪个 agent 在线，谁都可以连过去」** —— 那等于把 `SessionRuntime` 从
「这个会话被钉在哪」改成「现在是哪个 agent 在托管它」，于是那句 409
（「请到那台机器上打开它」）这个概念就没了。

设计与基数见 [architecture.md](architecture.md)「六者什么关系」。四个阶段：

| 阶段 | 做什么 | 买到的不变量 |
|---|---|---|
| 1 | `Workspace` 成一等对象，`session.workspace_id` 取代裸路径；`runtime` 降级为派生字段 | 服务端第一次**知道**工作区是什么，而不是二选一地猜。对外零变化 —— 这正是它安全的原因 |
| 2 | ~~容器工作区可命名~~ **✅ 2026-08-17 服务端 / 2026-08-18 界面** | 「容器里指定工作区」。不动路由、不动身份。⚠️ 服务端那半做完之后**界面隔了一版才接上** —— 期间这个能力在 HTTP 上活着而用户点不到，就是「造好了没人调用」那个形状 |
| 3 | ~~agent 上报在线名册~~ **✅ 2026-08-17 做完** | 「哪台机器」第一次成为可见信息，而授权规则一个字没改 |
| 4 | ~~中继 + 消息 FIFO 排队~~ **✅ 2026-08-17 做完** | Web 上的一轮真的跑在你那台机器上；撞上「正在跑」的那句话不再被丢掉 |

阶段 1 是「大改小用」，但它是后三步共同的前提，而且它自己就修掉一件事：
**服务端现在没有能力按工作区路由**（`session_state.workspace` 是个裸路径字符串，
不带机器；项目的本机落地目录只存在客户端的 `workspaces.json` 里）。

#### 阶段 2–4 做完之后，阶段 1 还剩什么

2、3、4 都是在**不动**阶段 1 的前提下做出来的，所以有必要说清它现在的处境：
它不再是「后三步的前提」，而是一次**内部整理**。

能不做阶段 1 而做出接入，是因为路由的判据从来没有落在服务端的数据上 ——
它落在「哪个 agent 拿得出这份绑定」，而那是 agent 自己报的。这正是 model.rs 里
那条论证的兑现（见下面「设备身份」一节）。

阶段 1 现在剩下的价值有两条，都不是能力：
- `session_state.workspace` 是个裸路径字符串，服务端**存着一个它无法解释的值**
- `runtime: Cloud|Local` 一个字段承担两件事（文件在哪、谁跑这一轮）

也就是说它值得做，但**它挡不住任何东西**了 —— 于是排在别的能力后面。

#### 调研改掉的两处

**① 单写者租约 → 消息 FIFO 排队。** OpenHands 踩过我们推演出的那个 bug
（WebSocket 收到消息就直接 `run=True`，多个执行循环同时跑），修法不是拒绝第二个
客户端而是**排队**：agent 忙时进 FIFO，当前这轮跑完再处理，另有一把 state lock。
比租约好在第二个客户端发的话不会被顶回来，而且对我们几乎免费（`/sync` + `/ws`
已经在，episodes 本来 append-only）。

**② 中继看到明文这件事有解。** VS Code dev tunnels 的分层是「WebSocket 中继层
由 connect JWT 认证 + SSH over WS 做端到端加密」，于是中继**读不到内容** ——
对自托管是净赚：agentd 当中继时不必被信任。服务端用的 `russh` 是 Rust 的。

> **② 还没做。** 阶段 4 的中继是明文的（agentd 读得到这一轮的全部内容）。
> 对当前部署不构成新的暴露 —— agentd 本来就存着全部消息、也是它在调 LLM。
> 端到端加密要买到的是「**自托管者不必信任中继方**」，那是给「agentd 由别人
> 运营」那种部署准备的，现在还没有那种部署。做的时候记住：真正的判据是
> **agentd 不再需要看内容**，而不是「加了一层 TLS」。

#### 阶段 4 落地时改掉的一处

调研里没预料到、真机上撞出来的：**通告地址与监听地址是两回事**。

第一版只有 `--allow-remote-attach`，通告的就是实际监听到的那个地址。它在
「机器直接暴露端口」这一种情形下对，而那不是常态 —— NAT、端口映射、
Docker Desktop 上那个属于 WSL 而不属于 Windows 宿主的网关地址，
三种情况下能监听的地址都**不是**别人够得到的那个。于是有了 `--attach-addr`。

拒绝 loopback / 通配符这条校验也因此必须验**通告的**那个地址，不是绑定的那个：
`--bind 0.0.0.0:8090 --attach-addr 203.0.113.7:8090` 是完全正当的组合。

#### 设备身份：**降级成路由提示，不做授权依据**

`model.rs` 里那条论证不能推翻（「本机绑定存在 `workspaces.json`，天然只在那一台
机器上，那本身就是设备检查 —— 比一个 device id 更硬，id 在重装/克隆之后会骗
人」）。所以在线名册里的 `machine_hint` 只用于**找人与界面文案**，真正的判据仍然
是「那个 agent 拿不拿得出这份绑定」—— 一个撒谎的 id 在它声称能跑那一轮时当场
被抓。

#### 三件明确不做

- **挂宿主机路径进云容器** —— 那是 `ExecEnvironment` 刻意留空的第三格（无隔离 +
  默认免确认 + 服务器全盘）。除非部署明确单用户自托管**且**那种会话强制回到逐条
  确认
- **抄 OpenHands 的 `session_api_key`** —— 维护者自己说它是「bearer + 沙箱绑定，
  不是有意义的第二因子」，而他们 issue 里在求的降权凭据**我们已经有了**
- **在阶段 4 之前给 agentd 加长连接** —— 它现在的失败模型是「起不来就不启动」，
  加长连接会多一类「半死」状态，而那要有在线名册才诊断得清

依赖 D2（得先有本地 agent 可挂）。

> CLI 会渲染工具事件、能答确认；Web 有附件上传下载、图片理解、
> markdown + 代码高亮。**唯一由架构决定的限制是「不能操作你机器上的文件」**。

> [architecture.md](architecture.md)「CLI 与 Web 现在到底能做什么」。

### G · 派 agent 去云上干活 —— **机制已经有了，缺的是产品化**

「让 agent 自己在别处跑一段时间，回来交活」这个能力今天就有，
**但不是这一节原先写的那个机制**。

> ⚠️ **这一节的前提换过一次，值得记一笔。**
> 原先写着「cortexd 里已经有 `Live::workspace_turn` 与会话绑定工作区
> （`bind_workspace`），服务端那条循环本来就是一个云上工作区 agent，
> 所以别删」。**那条循环后来还是删了** —— 理由不是它没用，而是它是
> **第二份 agent 实现**：同一个 `Turn::run` 有两处装配，每加一个工具、
> 每改一次注入纪律都要记得改两遍，而漏掉的那一遍没有任何测试会红。
>
> 能力没有消失，换了个宿主：**cortex-agentd 拉起一个容器，里面跑的是
> 同一个 `cortex-local`**（只多一个 `--exec-env=container`）。
> 于是「派出去」与「在本机跑」共用一份循环，而不是两份。

| 场景 | 走哪条 |
|---|---|
| 改我本机的代码 / 文档 | 本机 `cortex-local` |
| 派出去干活，关掉笔记本也照跑 | 容器里的 `cortex-local`（agentd 按需拉起） |
| 没有在线桌面时随便聊两句 | 同上 |

要补的部分：给它一个明确的入口（「派出去」，而不是碰巧开了云沙箱）、
~~任务状态可见~~（**已落地**，见下）、~~跑完通知~~（**已落地**，见下）。

> ✅ **跑完通知**（2026-08-19）。此前跑完的表现是侧栏徽章从「在跑」变成
> **什么都没有** —— 而「什么都没有」与「从来没跑过」长得一模一样，于是
> 用户只能隔一会儿点进去看一眼，而那正是这个能力想省掉的事。
>
> 现在 `ChatState.finished` 记「人不在的时候跑完的」那些会话：侧栏画一个勾
> （不是第二个圆点 —— 两个只有颜色不同的点在色弱视角下与「在跑」分不开，
> 而这两件事的下一步完全相反），同时弹一条带「去看看」的提示。打开就清。
>
> ⚠️ **这是应用内的通知，不是操作系统级的。** 桌面端最小化、或者浏览器
> 标签页在后台时，用户看不到它。补那一半要引入一个通知插件（Windows /
> macOS / Linux 三套原生通道）与权限流程，是独立的一件事 ——
> 在它落地之前，这里不声称「会通知你」，只声称「回来就看得见」。

> ⚠️ **「不是新架构」这句只对了一半**（2026-08-15 核过代码）。
> 执行侧成立，观测侧当时一格都没有。**观测侧那一半在同一天补上了。**
>
> **执行侧一直是对的。** 轮次跑在一个独立的 `tokio::spawn` 里，与 SSE
> 响应解耦；客户端断开不中止它，episode 照常落进记忆；容器的空闲回收看
> 「令牌多久没被用过」，跑着的轮次一直在续命。**关掉浏览器，活还在干。**
>
> **观测侧原先是空的**：事件发往一个已经被丢弃的 channel，人回来只能等
> episode 落库。现在有 `crates/cortex-local/src/runs.rs` —— 一份轮次登记簿，
> 带保序的重放缓冲与广播：
>
> | | |
> |---|---|
> | `GET /runs` | 这个进程上还在跑的那些 |
> | `GET /runs/{session_id}` | 挂上去（**重放 + 后续拼成一条 SSE**） |
> | `GET /sandbox/runs/{id}`（agentd）| 同一件事，多穿一层容器 |
>
> 客户端在 `selectSession` 时自动试挂，挂不上（404 / 旧后端 / 断网）一律
> 静悄悄 —— 绝大多数会话此刻都没在跑，任何噪音的代价是每打开一个旧会话
> 都来一次。
>
> **「哪些会话在跑」这个列表没做，而且这个仓库做不了。** 会话表在记忆
> 服务，`SessionDto` 加不了字段；agentd 也枚举不出某个用户有哪些容器
> （`scope_key` 由 owner 与项目派生，只有记忆服务算得出）。要一份完整
> 列表就得动 Cormex。
>
> 替代方案是**客户端自己记**「我发出去还没见到收尾的」（`ChatState.unfinished`）：
> 不需要任何后端、桌面端与云端同一份代码，且恰好覆盖真实场景 ——
> 「我发完就走了，回来看看」。局限是别的设备起的轮次看不到。
>
> 顺带纠正了三处在「客户端会一直连着」这个前提下写的行为，见那次提交：
> `bridge_events` 里「send 失败就 break」（没人看时连工具调用都不记）、
> 确认因「此刻没人连着」提前放弃（而人会回来答）、以及同一会话并发两轮
> （现在 409）。
>
> **E 要的是同一套机制**，所以它现在也只差一个入口了。

> **这里有个我们独有的东西**：派出去的 agent 与你共用**同一个记忆权威**。
> 它在云上学到的东西直接进你的记忆，回来不用「汇报」——
> Devin 那类云 agent 的产出是一个 PR，学到的过程随容器一起消失。
> 这一条值得在演示里专门做一遍。

### H · 工具是写死的 —— 按需加载与插件化

**现状（2026-08-25 重核了一遍）**：工具从定义到分发仍然全是硬编码，

| 在哪 | 是什么 |
|---|---|
| `tools.rs` `builtin_specs()` | 一个 `vec![]` 字面量，现在是 9 个 `ToolSpec`（2026-08-15 记的是 6 个） |
| `tools.rs` `execute()` | 一个 `match call.name.as_str()`，每个工具一条臂 |
| `turn.rs` 三处 | 直接调 `builtin_specs()`，各自再过滤 |

加一个工具 = 改同一个文件的两处 + 顾到三个调用点。而**由宿主执行的那些**
（`web_search`、`library_*`、`mcp_resource`、生图、电脑操作…）根本不进
`execute`，它们由 agent 循环在更外层按名字拦截分派。也就是说分发早就裂成
两层了，那本身就是「这里该有一张表」的信号。

> 半个月里这张表唯一的变化是「6 个」变成「9 个」，而两处硬编码一处没动 ——
> 这恰好印证了下面第 2 条的结论：**它挡不住任何东西**。这段时间里加了
> 十几个工具，每一个都是照着这三处抄一遍，没有一次因为「没有注册表」
> 而做不下去。

> ⚠️ **上面这张表是 2026-08-15 上午的现状，下午第 1 条就做完了。**
> `builtin_specs` 与 `execute` 那两处硬编码**照旧**（第 2 条没做），
> 但工具目录已经不只有内置的了 —— 见下面第 1 条。

~~**更要紧的一条：我们不是 MCP 客户端。**~~ **2026-08-15 起是了。**

此前 `rmcp` 只用来借 `Tool` 这个类型，没有任何 client transport，于是
第三方 MCP server 一个都接不进来 —— 而我们信这套原语信到把核心资产
（记忆）按它组织成 server 交出去。**只当供给方不当消费方**，那是不对称的。

#### 两家的做法

**[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）
—— 一切皆插件。** Cordis 内核只管挂载 / 卸载 / 依赖，其余**全部**是插件：
模型、工具、skills、会话、沙箱、存储、循环、调度、UI。核心概念是
**Capability Seam**：Service Definition 声明接口（`ctx.llm`、`ctx.fs`），
Service Provider 实现它（`llm-deepseek`、`fs-local`），Consumer 消费它
（通常就是面向模型的工具，如 `tool-bash` 消费 shell 能力）。
**没有需要打补丁的特权核心** —— 扩展方式是在别的插件旁边挂一个新的，
注册是副作用，卸载时干净回滚。配置层用 profile / bundle 分层组装
（`dsh-base` → `dsh-web-app` / `dsh-headless`），运行模式里那个
**Minimal 只留 shell 与文件编辑器**，专门用来给模型做 benchmark。

**[pi](https://github.com/badlogic/pi-mono)（Mario Zechner）—— 反方向的
同一件事。** 核心极简到 ~150 词系统提示 + 四个工具（read / write / edit /
bash），**刻意没有** sub-agent、plan mode、MCP、后台 bash，然后靠扩展把这些
全加回来。扩展是 TypeScript Extension / Skill / Prompt Template / Theme，
打成「Pi Package」用 npm 或 git 分发，支持热重载。它在 TerminalBench 上
排第二 —— 也就是说**砍到只剩四个工具并不掉分**，值得记住。

#### 对我们意味着什么 —— 三条，按确定性排序

**1（最确定）· 接 MCP 客户端。—— 已完成（2026-08-15）**

`cortex-mcp`：stdio 与 HTTP 两种传输、配置与 Claude Code 通用、设置页
（列表 / 详情 / 粘贴添加 / 官方注册表）、连接失败逐台可见。

**这条直接改变了 F 的做法**：文档生成不用自己写，挂一个 Office 类
MCP server 就有；图片生成仍要自己写，因为难点（选哪家、谁付钱、key 存哪儿）
MCP 一点都没省下来。

做的过程里撞出两个 bug，都是「不报错」那种，值得记下来：

- **`chat_turn` 是启动时建好的 `Turn::sealed()`**，外来工具只并进了绑了
  工作区那条路。于是「配好 MCP + 开个没绑工作区的会话」= 一个外来工具都
  没有，而模型只是表现得不会用那个功能。治法不是给它也并一次（那就是第三处
  装配），是**删掉那个字段、两条路都现搭**
- **连接一处超时都没有。** `serve()` 与 `list_all_tools()` 都可能永不返回
  （子进程起来了但在等 stdin、HTTP 端点接了连接就沉默），而逐台连接是串行
  的 —— 后果是**整个 agent 起不来**，桌面端卡在「正在启动 agent」，日志最后
  一行指向那台 server，看起来像它的问题。`McpHub` 文档里「一台起不来其余
  照常」那句承诺，没有这道超时就是假的

**2（中等）· `builtin_specs` + `execute` 换成注册表。** 纯机械重构，
收益是「加工具不改 match」。

> **它不再是第 1 条的前置了。** 原先的判断是「从 MCP 来的工具得能和内置
> 工具进同一张表」，实际做下来更简单：`ToolSpec` 加一个 `source` 字段
> （`Builtin` / `External`），分发按**类型**分岔而不是按 match 的兜底顺序。
> 也就是说这条现在是纯粹的内部整洁，没有功能挡在它后面 —— 优先级该降。

**3（最不确定）· 要不要走到 dsh 那种「循环 / 存储 / UI 都是插件」。**
Rust 没有 dsh 那种 ESM 动态挂载的运行时便利，做成动态库插件是另一个量级
的事（ABI 稳定性、崩溃隔离、版本矩阵）。我们的 seam 更可能长成
**「进程内注册表 + 进程外 MCP」两层**，而不是一个通用内核。
**这一条要有明确需求再动** —— 别为了对齐一个架构名词，付编译期与
安全边界上的真钱。

#### 一条必须写在前面的：权限是我们已有的 seam

`ExecEnvironment` + `Risk` + `ApprovalPolicy::decide` 是按**爆炸半径**
组织的，而任何从外部挂进来的工具**必须落进同一个闸门**。

这是接第三方工具时第一个要想清楚的问题，而两家都没有替我们回答：
dsh 的审批策略放在 `dsh-base` 里（是插件，也就是可以被换掉），
pi 干脆不谈这件事。

具体要定的是：**`ToolSpec.risk` 由谁声明？** 一个外来的 MCP server
自称它的工具是 `Risk::Safe`，我们该信吗？照现在的类型，
`decide` 只在 `risk < confirm_at` 时放行 —— 让调用方自报风险等级，
等于把闸门的钥匙交给被闸的人。

#### 这个问题在 2026-08-15 定了

**不信对端，信用户。** 三条，写在 `ToolSpec::external` 与 `config::Trust` 上：

1. **外来工具一律 `Risk::Execute`**（最高档），构造函数里写死，不读对端的
   `annotations.readOnlyHint` —— 那个字段是**服务端自报**的
2. **唯一能降档的地方是用户自己的配置文件**里的 `trust`（`ask` / `write` /
   `trusted`）。字段名刻意不叫 `risk`：配置要表达的是「我多信它」，
   不是「它有多危险」—— 后者我们判断不了
3. **名字强制加前缀** `mcp__{server}__{tool}`，构造函数里拼，外来工具因此
   **不可能**顶掉一个内置工具的名字

设置页把第 2 条摆在明面上（三档 + 一句为什么默认是「每次询问」）。
两家参考实现都没回答这个问题：dsh 把审批策略放进一个可以被换掉的插件，
pi 干脆不谈。

## 并行策略

非冲突任务交子 agent 并行。冲突面按**目录**划，不按功能划——
功能会互相牵扯，目录不会。

拆分之后这个仓库的天然切面是四块，互不重叠：

| 目录 | 谁在这儿干活 |
|---|---|
| `crates/cortex-agent` + `cortex-local` | 循环、工具、沙箱、权限 |
| `crates/cortex-agentd` + `cortex-store` + `migrations/` | 编排、持久层、路由 |
| `app/` | Flutter（桌面 + Web 一套） |
| `scripts/` + `ansible/` + `.github/` | 运维与发版 |

**加一个工具会同时落在前两块**（spec 在 `cortex-agent`，宿主实现在
`cortex-local`，路由在 `cortex-agentd`）—— 那种活**串行做或者一个 agent
包圆**，别拆。判据不是「改了几个文件」，是「有没有一处漏改是编译器发现
不了的」：`Caps::any()` 那次就是漏在两块之间。

> 上一轮四个 agent 的边界写的是 `cortexd`，那个 crate 2026-08 拆走了。
> 留这一句是因为**并行边界会随架构漂**，照着旧边界分工的第一个症状是
> 两个 agent 同时改一个不存在的目录。
